# 城迹 CityTrace

**记录一段真实走过的城市路线，整理沿途地点和照片，让别人按这条路线再走一次。**

当前版本：**MVP V2.1**。适合本地体验、团队演示和受控的真实路线测试。

> 这是可运行的项目源码。GitHub 仓库页面不是在线应用地址；克隆并启动服务后，才能在浏览器中使用。
>
> **想用手机真正记录 GPS，请先配置 HTTPS。**同一 Wi-Fi 下的普通 HTTP 链接可以浏览、登录和手动复刻，但不能在手机浏览器中启动定位记录。高德 Key 用于道路底图，不是 GPS 采样的前提。

## 1. 这个产品是做什么的

CityTrace 以实际 GPS 记录为基础，将一段行程整理为城市路书：

```mermaid
flowchart LR
    A["真实 GPS 记录"] --> B["保存私有草稿"]
    B --> C["添加有序地点与现场照片"]
    C --> D["确认相邻地点的交通方式"]
    D --> E["检查隐私并提交审核"]
    E --> F["管理员审核公开"]
    F --> G["其他人收藏、分享与复刻"]
```

例如：你从街口步行到一家小店，再坐地铁到下一站。记录完成后，可以为三个地点上传现场照片，分别填写两段交通方式，提交审核后供他人参考。

“复刻”指按原作者的路线和站点顺序重新体验；原作者的轨迹与复刻者的 GPS、到站进度分别保存。

## 2. 目前能做什么

| 功能 | 当前行为 |
|---|---|
| 发现路线 | 浏览审核通过的路线，按关键词、城市、主题和时长筛选，支持分页 |
| 路线地图 | 查看公开轨迹；配置高德后显示道路底图，未配置时显示有明确说明的坐标线稿 |
| GPS 记录 | 前台定位采样、暂停、继续、结束、同步状态和有限离线队列 |
| 路线编辑 | 修改名称、城市、主题、简介、封面，添加地点、照片和位置来源 |
| 路段编辑 | 根据相邻地点形成路段，确认步行、地铁、公交、骑行等交通方式 |
| 发布审核 | 私有草稿提交后进入审核，通过后才对其他用户公开 |
| 收藏与分享 | 保存喜欢的公开路线，通过系统分享或复制链接分享 |
| 复刻行程 | 查看固定版本的原路线、照片和下一站，手动确认到站，独立记录本次 GPS |
| 个人管理 | 查看自己的路线、收藏和复刻历史，撤回符合条件的公开/审核中路线 |
| 管理员工具 | 审核路线、处理举报、下架公开路线 |
| 手机界面 | 底部导航、适配窄屏的表单、照片预览、带安全区的路线操作栏 |

权限分为三类：

- **游客**：浏览已公开路线。
- **注册用户**：记录和编辑自己的路线，上传照片、提交审核、收藏和复刻。
- **管理员**：在普通用户功能之外，审核、下架路线并处理举报。管理员身份不代表可以任意修改其他人的原始 GPS。

## 3. 快速启动：推荐 Docker

### 准备

安装 Git、Docker，以及支持 `docker compose` 的 Docker Compose。使用 Docker Desktop 时，先打开 Docker Desktop，等引擎启动。

### 第一步：下载项目

```bash
git clone https://github.com/JB54088/city.git
cd city
```

### 第二步：创建本机配置

首次克隆后执行：

```bash
cp .env.example .env
```

Windows PowerShell 也可使用：

```powershell
Copy-Item .env.example .env
```

`.env.example` 默认是演示模式和本机端口 `8002`。首次体验可保持不变；以后更新项目时，保留自己的 `.env`，不要重复覆盖。

### 第三步：启动

```bash
docker compose up --build -d
docker compose ps
```

当服务状态显示 `Up`，随后显示 `healthy`，打开：

**[http://127.0.0.1:8002/#/discover](http://127.0.0.1:8002/#/discover)**

也可以检查：

```bash
curl http://127.0.0.1:8002/health
```

正常响应中会有 `"ok":true` 和 `"status":"ready"`。

如果没有复制 `.env.example`，Compose 自身的备用主机端口是 `8000`。如果你修改了 `CITYTRACE_PORT` 或绑定了局域网 IP，请使用修改后的地址。第一次构建需下载 Python 基础镜像，因此需要能连接镜像仓库。

### 常用控制命令

```bash
docker compose ps                  # 查看状态
docker compose logs -f citytrace   # 查看日志，Ctrl+C 仅退出日志查看
docker compose restart citytrace  # 重启服务
docker compose stop citytrace     # 停止服务，保留容器和数据
docker compose start citytrace    # 启动已停止的服务
docker compose down               # 移除容器，保留数据卷
```

**普通停止不要加 `-v`。**`docker compose down -v` 会删除项目的数据卷，包括数据库和上传照片。

### 不使用 Docker：Python 启动

需要 Python 3.9 或更新版本。应用运行时使用 Python 标准库，不需要安装 Node.js、npm 或运行前端构建。

```bash
git clone https://github.com/JB54088/city.git
cd city
python3 app.py
```

打开 **[http://127.0.0.1:8000/#/discover](http://127.0.0.1:8000/#/discover)**。Windows 可使用 `py -3 app.py`。

直接运行 Python **不会自动读取 `.env`**。需要读取配置时，按[部署手册](docs/DEPLOYMENT.md#python)加载环境变量。

## 4. 五分钟体验：不必先出门记录

默认 `APP_MODE=demo` 会创建明确标注的福州演示路线和以下账号：

| 身份 | 邮箱 | 密码 |
|---|---|---|
| 路线作者 | `author@citytrace.demo` | `trace123` |
| 体验用户 | `explorer@citytrace.demo` | `trace123` |
| 管理员 | `admin@citytrace.demo` | `admin123` |

1. 打开“发现”，查看演示路线和详情。
2. 点击“登录 / 注册”，使用体验用户登录。
3. 点击“收藏路线”，到“行程 → 已收藏”确认结果。
4. 打开详情，点击“开始复刻”。
5. 查看当前目标、现场照片和交通方式；到站操作使用“确认到站”。
6. 体验暂停、继续和“完成复刻”，在“行程 → 复刻记录”查看结果。
7. 想看审核入口，退出当前账号后，用管理员登录，进入“我的 → 审核工具 → 打开管理后台”。

普通 HTTP 下可体验浏览和手动复刻。开启本次复刻 GPS 或创建自己的定位记录，需要安全连接和位置权限。

演示内容用于理解操作，不能冒充自己的真实路线重新发布。`demo` 模式下新建的测试记录也保存在演示库；实际收集真实行程前，建议切换独立的 `real` 模式。

## 5. 从体验到真实使用

完整步骤是：

1. 配置 `APP_MODE=real`，首次启动时设置管理员邮箱和至少 12 位密码。
2. 为测试手机提供其信任的 HTTPS 地址，开启系统及浏览器位置权限。
3. 注册普通账号 A，在“记录”中完成一段真实行程并保存草稿。
4. 在草稿中添加至少两个有序地点，每个地点至少一张现场照片。
5. 确认每个相邻地点之间的交通方式，保存路线信息。
6. 检查隐私范围，勾选确认后提交审核。
7. 管理员审核通过。
8. 用普通账号 B 打开公开路线，收藏并开始复刻。

详细按钮、发布条件和注意事项见[完整使用手册](docs/USER_GUIDE.md)。手机 HTTPS 和地图配置见[部署手册](docs/DEPLOYMENT.md)。

## 6. 数据保存在哪里

| 启动方式 | 数据位置 |
|---|---|
| 直接运行 Python，演示模式 | `data/demo/citytrace.sqlite3` 和 `data/demo/uploads/` |
| 直接运行 Python，真实模式 | `data/real/citytrace.sqlite3` 和 `data/real/uploads/` |
| Docker | 容器 `/app/data/` 下同样的 `demo/`、`real/` 目录，存放在 `citytrace_data` 命名卷中 |

Compose 通常给数据卷加项目名前缀；在名为 `city` 的目录默认启动时，一般为 `city_citytrace_data`。使用 `-p` 或 `COMPOSE_PROJECT_NAME` 后名称会变化。

演示库与真实库互相独立。切换模式不会把演示账号和路线迁入真实库，也不会自动删除另一套数据。已有数据库启动时按顺序迁移，V2.1 没有新增第四次数据库迁移。

`.env`、数据库、上传文件、证书、私钥和本机备份不属于需要上传的项目源码。

## 7. 技术结构与开发入口

当前实现是 **Python 标准库 HTTP 服务 + SQLite + 原生 HTML/CSS/JavaScript**。

```text
city/
├── app.py                         # HTTP 服务、认证、业务接口、迁移及模式初始化
├── docker-compose.yml             # 容器、端口、环境变量和持久化卷
├── Dockerfile
├── .env.example                   # 配置模板
├── migrations/                    # 三次增量数据库迁移
├── static/
│   ├── index.html                 # 应用外壳和导航
│   ├── app.css                    # 桌面、平板和手机布局
│   ├── app.js                     # 通用交互与基础业务流程
│   ├── v2.js                      # 地图、地点、照片、编辑及复刻增强
│   ├── sw.js                      # 离线应用外壳
│   ├── manifest.json
│   └── icon.svg
├── tests/
│   ├── test_api.py                # API、权限、数据及迁移回归
│   ├── playwright_smoke.cjs       # 只读浏览器冒烟
│   ├── mobile_experience.cjs      # 手机布局、编辑、发布等交互回归
│   └── recording_regression.cjs   # 模拟 GPS、同步及缓存回归
└── docs/
    ├── USER_GUIDE.md              # 按页面和按钮编写的使用手册
    ├── DEPLOYMENT.md              # 配置、手机访问、备份、升级和测试
    └── API.md                     # REST 接口参考
```

接口以 `/api` 为基础路径，登录使用 HttpOnly 会话 Cookie。开发时先阅读 [API 文档](docs/API.md)，测试命令和隔离测试数据库的方式见[维护与测试](docs/DEPLOYMENT.md#maintenance)。

## 8. 当前限制

- 这是受控测试 MVP，尚未进行公开运营或高并发容量验收。
- 浏览器 GPS 只在前台采集。锁屏、切换应用、系统回收页面或关页都可能中断记录；不支持原生后台持续定位。
- 未配置高德时没有道路底图，也不能在底图上选点；仍可记录 GPS、查看坐标线稿和填写实际位置。
- 路线是历史行程参考，不保证道路、店铺和交通线路目前仍然可达；道路导航交给外部地图。
- 隐私裁剪按起终点各约 150 米计算，不会自动隐藏每个打卡地点或照片中的敏感信息。
- 离线能力是应用外壳和有限采样队列，不是完整的离线地图、离线路线库或离线发布。
- 当前没有密码找回、邮件通知、对象存储、原生 App 和自动偏航告警。请妥善保存测试账号密码。
- 撤回/下架后尚无作者在界面中直接重新上架的完整流程；账号删除为停用和保留历史数据，不是物理清空。
